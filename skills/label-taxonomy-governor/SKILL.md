# 标签体系设计与文案合规器

把「标签」这件事拆成两个不混用判据的域：**A 域能设计出一套体系，B 域能审清楚一份文案**。

> 版式与视觉设计不在这里，走 `label-visual-designer`；两份结论分开出。

**五条纪律，先记住：**

1. **先分流，不混用判据。** 同一个「这个标签不行」，在 A 域是维度不正交／口径漂移，在 B 域是强制标注缺失／禁用词。没分流就开始查，等于没查。
2. **先设计，后校验。** A 域新建体系必须先走 D-Q-D-V 与标注指南，再跑覆盖度脚本。**脚本只能判断已提出的方案，不能生成方案**。
3. **脚本只查结构，不判定。** 脚本能找出命名违规、枚举重复、跨文件取值冲突、覆盖度异常、分域禁用词命中，但**不能判断某句话是否合法合规，也不能判断标签是否贴合业务**。
4. **没跑脚本就不许说跑过。** 报告首行必须是 `【执行声明】脚本：已运行（N 项）｜未运行（人工逐条）`。
5. **项目自述 ≠ 法规原文。** 化学品标签规则包里的条款号来自用户项目材料自述引用、法规原文未取到，一律标 `[I]` / `依据：待核实`；**不得把项目自述升格为法规结论**，也不得据此判断是否违法。

## 触发条件

- 要为一批内容／商品／用户**从零设计**标签体系，或要给现有标签定命名与取值规范
- 要写标注指南、划易混淆边界、定标签生命周期
- 要验收一套体系的覆盖率、长尾值、关系冲突
- 同一标签在规格表、配置、代码常量、文档里取值对不上，要定位漂移点（含中文口径键）
- 一份产品／包装标签文案要下厂或要上架，需核强制标注与禁用词
- 标签含 GHS 象形图、警示词、SDS 信息、UN 编号 → 走化学品标签规则包
- 标签用词被内部判「过强」，但官方技术文件用了同一个词，需要判定是否恢复

## 输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 域 | ✅ | A 数据／内容标签体系、B 商品／包装标签文案、跨域（分别出结论）。**v1.2.2 起脚本输入必须显式写 `domain`：`"A"` 或 `"B"`；缺省按 A 处理。A 域输入即使携带 `scope` 也不采信、不输出 B 域属性认定与禁用词结论。** |
| A 域新建：业务**决策**清单 + 业务对象清单 | A ✅ | 设计必须从决策出发 |
| A 域验收：现有标签表 + 标注样本 + 关系矩阵 | A ✅ | 用于覆盖度与关系冲突校验 |
| A 域治理：口径声明 | A ⭕ | 支持中文与英文口径键；跨语言同义键写进 `key_aliases` |
| B 域：标签文案全文 | B ✅ | 要上机的那一版全文，不是摘要 |
| B 域：产品属性认定依据 | ⭕ | 农药／化妆品／食品／**工业化学品**／普通商品；缺失标「需人工复核」，不替用户猜 |
| B 域化学品：各自 SDS／MSDS 原件 | ⭕ | 无 SDS 时只能做材料完备性核查，标「不得直接印制」 |
| 目标印厂规范 / 项目内部规范 | ⭕ | 用户给了就以用户规范为准 |

> ⚠️ **不要用摘要做核查**。摘要会磨掉限定词、适用范围和版本号。

## 输出

1. **审查报告**（Markdown）— 执行声明 + 分流结论 + 三栏表 + 待拍板项 + 依据清单
2. **机器可读报告**（JSON）— 由脚本产出，字段结构稳定
3. **A 域新建时**（按 `templates/`）：规格书、标注指南、覆盖度报告、关系矩阵与生命周期表
4. **A 域治理时**：口径一致性报告（含 `format_only` 仅书写格式差异明细）
5. **B 域化学品时**：按 `domain-b-chemical-label.md` 的 11 项要素逐项三态

## 自检

用户说「跑自检／测试一下／检查安装」时，运行 `scripts/self_check.py` 并原样贴出输出（**28 条冒烟断言**）。

## 处理步骤

1. **分流**。判 A / B / 跨域，写进报告首段。跨域先出总检查清单，分别执行，**不合并成一句结论**。
2. **索取必要输入**。缺什么列什么，不替用户假设产品属性、业务决策、印厂规范、登记状态。
3. **A 域设计阶段（新建体系时先做）**：D-Q-D-V 决策链 → 粒度基数与五类关系 → 标注指南六项 → 设计评审四问。四问不过退回改。
4. **A 域验收 / 治理**：
   ```bash
   python scripts/check_taxonomy_coverage.py \
       --input examples/taxonomy-design-example.json --config config/rules.json \
       --output-md coverage.md --output-json coverage.json

   python scripts/check_label_consistency.py \
       --input examples/consistency-example.json --config config/rules.json \
       --output-md report.md --output-json report.json
   ```
   - 在技能根目录执行；两份示例均为包内真实文件，照抄即可运行。
   - 口径脚本读 `summary`、`conflicts`、`format_only`、`naming_violations`、`banned_hits`、`verdicts`。
   - **冲突不属四类时不发明第五类**：仅书写格式差异、待办句被当成值 → `需人工复核`；归一后仍不同才按四类定性。见 `verdict-taxonomy.md` 第八节。
   - 中文口径键自 v1.2 起正确分组；跨语言同义键补 `key_aliases`，不在脚本里硬编码项目名。
5. **B 域执行**：先做**属性认定**。出现 GHS 象形图／警示词／SDS／UN 编号时改走化学品规则包；**先判适用性再判缺失**，不适用的项不进缺失清单。
6. **逐条三态结论**。禁止「可能有风险」「基本没问题」单独成句。
7. **给依据**。格式 `依据：<文件/法规名称> <条款位置>`；法规原文未取到写 `依据：待核实`，**不编造条号**。
8. **单列待拍板项**。口径取舍、命名恢复、法规适用判断一律交回用户。
9. **汇总交付**。Markdown + JSON + 修复建议清单（按 `阻断交付 / 需修复 / 建议优化 / 需人工复核` 排序）。

## 脚本边界（务必如实转述给用户）

| 事项 | 脚本能做 | 脚本不能做 |
|---|---|---|
| 命名规范 | ✅ 正则、长度、保留词 | ❌ 判断名字在业务上是否贴切 |
| 枚举完整性 | ✅ 重复值、空值、类型混杂 | ❌ 判断枚举是否覆盖全部业务情况 |
| 跨文件口径 | ✅ 同口径键不同取值、中文键分组 | ❌ 跨语言换词表述 |
| 书写格式差异 | ✅ NFKC／空格／乘号归一后识别 | ❌ 判断哪种写法才是权威 |
| 覆盖度 | ✅ 覆盖率、维度使用率、未登记值、长尾值、单标签对象 | ❌ 判断业务有效性 |
| 分域禁用词 | ✅ 按 `scope` 匹配词表 | ❌ 判断整句是否构成违规宣称 |
| 化学品强制标注 | ❌ 脚本无专用词表 | ❌ 由模型按化学品规则包逐项核，标 `依据：待核实` |
| 法规效力 | ❌ 不联网、不查现行版本 | ❌ 必须由用户或法务复核 |

`config/rules.json` 缺失或格式错误时脚本**报错退出，不静默回退**。

## 判定与结论的归属

- **事实部分**由脚本与规则包决定，模型不得凭印象下结论。
- **定性部分**由模型判断，但必须写出依据句。
- **拍板**由用户决定。用户坚持保留一条 `不通过` 的内容时，如实记录「此条在已知风险下保留」，不重复劝阻。

## 注意事项

- 本技能**不构成法律意见**，不判断是否违法、不预测处罚。每份报告写「请复核法规现行有效版本」。
- **不宣称首创**；承袭／增量见 `experience-provenance.md`。
- **查不到 ≠ 不存在**：无工业化学品专用词表时只做材料完备性核查，须说明边界。
- **不适用 ≠ 缺失**：农药证号、化妆品禁用词表对化学品标签不适用，不进缺失清单。
- **项目自述 ≠ 法规原文**：化学品条款号一律 `[I]` / `依据：待核实`。
- **指标不达标 ≠ 业务无效**；小样本长尾偏高属结构现象，维度合并由用户拍板。
- **规则可配置**：阈值、词表、别名放 `config/rules.json`。
- 不刷长度。三段话说得清，不写三页。
