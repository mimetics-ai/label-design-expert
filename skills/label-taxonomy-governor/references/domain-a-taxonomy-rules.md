# A 域 · 数据／内容标签体系规则

> 适用：内容库标签、用户／商品画像标签、资料分类标签、系统内枚举标签、GitHub issue label。
> **不适用**：印在产品包装上的实体标签（走 `domain-b-label-compliance.md`）。

---

## 一、先定业务对象，再切维度

标签是给「某一类对象」打的。第一步必须写清对象是什么（一篇内容 / 一个 SKU / 一个用户 / 一次工单）。
对象没定就切维度，会出现一套标签里混着「内容体裁」和「用户年龄段」两套坐标系。

**维度正交检查（逐对问）**：

| 问句 | 不通过的样子 |
|---|---|
| 一个对象能否同时落在两个维度上，且互不冲突？ | 「渠道」和「发布平台」高度重叠 |
| 同一维度内的取值是否互斥？ | 「高价值」「重点客户」并存，边界靠人猜 |
| 维度是否能独立回答一个业务问题？ | 设了「其他」兜底维度，实际什么也答不了 |

> 不硬套 MECE。业务上确实需要交叉的（如「风险等级」×「处置状态」），明确写成**两个独立维度**，
> 而不是把组合值塞进一个维度的枚举里。

**层级深度**：默认 ≤ 3 层（维度 → 组 → 值）。超过 3 层时，先问是不是把两个维度压成了一个树。

## 二、命名规范

| 项 | 规则 | 配置位置 |
|---|---|---|
| ID 格式 | `kebab-case`，小写字母开头，仅字母数字与连字符 | `config/rules.json → naming.pattern` |
| 长度 | ≤ 40 字符 | `naming.max_length` |
| 禁用词 | `misc` / `other` / `unknown` / `temp` / `test` 等兜底词 | `naming.reserved_words` |
| 语义 | 用名词或名词短语，不用形容词、不用程度词 | 人工判定 |
| 别名 | 一个业务概念只允许一个规范 ID；旧名进别名表并标 `deprecated` | `config/rules.json → key_aliases` |

**反例**：`important`、`high-priority`、`other-tag` —— 前两个是程度判断会随人漂移，第三个是把分类失败藏进标签。

**正例**：`content-format`、`integrity-level`、`lifecycle-stage`。

## 三、取值与枚举

1. 每个维度的取值必须**穷举**，或明确写出「开放值域 + 取值来源」。
2. 枚举值类型一致（不要 `["Low", 2, "高"]` 混着）。
3. 值要有定义句，不能只有名字。`Medium` 要写清「什么条件下算 Medium」。
4. **指定单一事实源**：某标签的权威取值只允许一处声明，其他位置都是引用或镜像。规格书里必须写出这个位置。

## 四、四类口径漂移（优先级从重到轻）

同一标签在不同位置对不上时，只能落在这四类里。不在四类里，标 `需人工复核`，**不要临场发明第五类**——
发明类别会让判定标准随对话漂移，两天后同一句话给出两个结论。

| 类型 | 定义 | 判定问句 | 真实案例 |
|---|---|---|---|
| **值漂移** | 同一口径键，声明值不同 | 把两处值并排放，能同时为真吗？ | `gate-manifest.json` 与 `label-guard.mjs` 都声明 `Medium`，M2 计划 §3.5 仍写「当前 = `Low`」 |
| **名漂移** | 同一概念用了两个 ID，且无别名表 | 检索两个 ID，命中的是不是同一批对象？ | 「客户数」与「服务企业数」各建一套标签 |
| **范围漂移** | 定义句一致，但适用范围被悄悄扩大／缩小 | 原文的每个限定词（人群、时点、渠道）在新版里还在吗？ | 「近 30 天活跃」被写成「活跃」 |
| **版本陈旧** | 值改过，但文档／注释没跟着改 | 这份文本的最后更新时间是否晚于值变更？ | 实现已改 `Medium`，计划文档未同步 |

**优先级**：`值漂移 > 名漂移 > 范围漂移 > 版本陈旧`。
一句话同时命中多类时，按最重的那类出结论，不要把重问题写成轻问题。

> 真实案例来自本项目 `brand-delivery` 2026-10-14 工作日志第 8 条缺口（「标签口径文本陈旧」）。
> 它的教训不是「改文档就行」，而是：**文档与实现各写一份口径，迟早会漂**。所以要指定单一事实源。

---

## 五、修复方向（按类给药）

| 类型 | 修复方向 | 不要做 |
|---|---|---|
| 值漂移 | 回到单一事实源定值，其余位置改为引用 | 不要两边都改成「看起来都对」的第三个值 |
| 名漂移 | 定一个规范 ID，旧名进别名表并标 `deprecated` | 不要直接删旧标签，历史数据还在引用 |
| 范围漂移 | **缩口径**，把限定词写回去 | 不要删结论；话会变长但每个字都对得上 |
| 版本陈旧 | 改文档而不重命名已被锚定的脚本／配置常量 | 不要为了对齐文档去改实现里的常量名 |

## 六、A 域检查清单

- [ ] 业务对象已写清，且只有一类
- [ ] 维度两两正交，无重叠
- [ ] 层级 ≤ 3 层
- [ ] 每个 ID 通过命名正则，无保留词
- [ ] 每个维度取值已穷举，值类型一致，有定义句
- [ ] 指定了单一事实源
- [ ] 别名表齐备，旧名标 `deprecated`
- [ ] 已跑 `check_label_consistency.py`，报告首行有执行声明
- [ ] 漂移按四类定性，按优先级排序
- [ ] 待拍板项单列，没有替用户决定
