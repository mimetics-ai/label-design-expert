# 商品标签视觉设计器

把「标签文案」变成「可评审、可计算、可交给印厂的版式规格与样张」。

**三条纪律：**

1. **版式与合规分开判。** 本技能只管「放在哪、多大、什么颜色、能不能印」；文案写什么、能不能写，走 `label-taxonomy-governor` 的 B 域合规规则包。**版式通过 ≠ 文案合规**，两份结论分开出，不合并成一句。
2. **脚本只算几何与数值，不判合规。** `check_visual_spec.py` 能算对比度、字号下限、面积占比、静区、TAC，但**不能判断一句话是否违法、商标图样是否与注册证一致、配色是否符合品牌**。
3. **没跑脚本就不许说跑过。** 报告首行写 `【执行声明】脚本：已运行（N 项）｜未运行（人工逐条）`。

## 触发条件

- 要给产品／包装标签排版、出样张、定视觉规格
- 要判断最小字号、视距可读性、底色与字色对比度
- 要核商标位置／面积、二维码静区、出血与安全边距
- 要产出设计令牌供前端或印前复用

## 输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 成品尺寸 W×H（mm） | ✅ | 没有就明确要，不替用户假设 |
| 区块清单 | ✅ | 每个区块给 `id` / `type` / `x,y,w,h` / `font_mm` / `fg` / `bg` / `text` |
| 视距（mm） | ⭕ | 默认 400，采用默认值须在报告标注 |
| 印厂规范 | ⭕ | 有则覆盖 `config/visual-rules.json` 默认值 |
| 文案合规结论 | ⭕ | 若已跑过 B 域合规，附在报告里交叉引用；没有就注明「文案合规未核」 |

> 样张示例一律用**占位文案**，不得把演示稿当真实产品信息。见 `examples/label-proof-input.json` 的 `note`。

## 输出

1. `visual-spec.md` — 视觉规格表（按模板）
2. `visual-report.md` + `visual-report.json` — 版式校验报告（三态）
3. `label-proof.svg` — SVG 样张（可开标注层）
4. `tokens.css` / `tokens.json` — 设计令牌
5. 待拍板项（配色、字体、品牌取舍）

## 规则包

| 文件 | 用途 |
|---|---|
| `references/visual-spec-rules.md` | 五层信息层级、栅格、字号、对比度公式、商标/码/印刷规则、评审五问 |
| `config/visual-rules.json` | 可配置阈值：字号、对比度、面积比、静区、TAC |
| `templates/visual-spec-template.md` | 视觉规格表模板 |
| `examples/label-proof-input.json` | 可运行示例（占位文案） |

## 自检

用户说「跑自检／测试一下」时，运行 `scripts/self_check.py` 并原样贴出输出（14 条冒烟断言）。

## 处理步骤

1. **确认尺寸与区块**。缺尺寸或坐标就列出来要，不猜。
2. **确认印厂规范**。有规范就覆盖默认值；没规范在报告写明「采用默认值，需印厂确认」。
3. **版式校验**：
   ```bash
   python scripts/check_visual_spec.py \
       --input label-proof-input.json --config config/visual-rules.json \
       --output-md visual-report.md --output-json visual-report.json
   ```
4. **渲染样张**：
   ```bash
   python scripts/render_label_proof.py \
       --input label-proof-input.json --output label-proof.svg \
       --tokens-css tokens.css --tokens-json tokens.json --annotate
   ```
5. **逐项三态结论**：`通过` / `不通过` / `需人工复核`。需人工复核必须写明不确定在哪（如「商标图样一致性需比对注册证」）。
6. **设计评审五问**，见规则文档第七节；未过的退回规格表改。
7. **交叉引用合规结论**：文案合规已核 → 引用其报告；未核 → 明确写「本次仅做版式，文案合规未核」。
8. **单列待拍板项**：配色、字体、品牌表现一律交回用户。

## 脚本边界（务必如实转述）

| 事项 | 能做 | 不能做 |
|---|---|---|
| 对比度 | WCAG 2.1 公式算比值 | 配色是否好看／符合品牌 |
| 字号 | 类型下限 + 视距下限 | 字体选择 |
| 几何 | 安全边距越界、四角判定、面积比 | 视觉平衡 |
| 二维码 | 边长、静区、越界 | 扫码验证内容 |
| 印刷 | TAC、线宽、K 值、dpi 数值 | 实际印刷效果 |
| 层级 | L1 存在且字号 ≥ L4 | 文案是否合规／夸大 |
| 法规 | ❌ | 由用户／法务复核 |

`config/visual-rules.json` 缺失或格式错误时脚本**报错退出，不静默回退**；报告须如实说明脚本有没有跑成功。

## 判定与归属

- **数值部分**（对比度、字号、面积比、静区、TAC）由脚本决定，模型不得凭印象下结论。
- **定性部分**（信息层级是否真的清晰、品牌表现是否合适）由模型判断并写出依据句。
- **拍板**：配色、字体、取舍由用户决定。用户坚持保留一条 `不通过` 的版式时，如实记录「此条在已知风险下保留」，不重复劝阻。

## 注意事项

- 样张是**设计稿不是印稿**，不含真实产品信息，不得直接下厂。
- 版式参数来自通用实践与用户既有印前规则，**须与印厂确认**；法规类条款须复核现行有效版本。
- **不宣称首创**：承袭／增量见 `references/visual-spec-rules.md` 第零节与 `label-taxonomy-governor/references/experience-provenance.md`。
- 不构成法律意见，不替代印厂工艺确认。
