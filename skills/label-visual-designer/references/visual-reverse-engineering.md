# 既有标签逆向工程与实测回灌（v1.2.0）

## 零、承袭与增量

- **承袭**：2026-11-19 桌面标签审查任务（13 款树脂标签 + 66 款涂料背标）与 H100Z 背标真实改版任务的实际做法；包内 `visual-spec-rules.md` 的五层层级、栅格、WCAG 2.1 与印前参数。
- **增量**：把当时临时写的 `measure_back.py`／`layout.json` 做法固化成可复用步骤与输入契约；新增像素取整、中文禁则、文件名裁切三类踩坑的判据。
- **不宣称首次发现任何标签设计规律**。本文件只描述「怎么把已有标签变成可校验输入」，不生成设计。

## 一、什么时候用

| 任务 | 走哪条 |
|---|---|
| 从零设计一张标签 | `visual-spec-rules.md` + `render_label_proof.py`（占位样张） |
| **审查已有的真实标签图／源脚本** | 本文件：先反算成机器可读输入，再跑 `check_visual_spec.py` |
| **拿一张真实标签做改版** | 本文件第三节闭环 + `templates/redesign-spec-template.md` |

关键区别：审查既有稿时**不能目测坐标**，也不能把文件名里的尺寸当成成品尺寸。

## 二、四步：从像素到可校验输入

### 第 1 步 · 确认成品尺寸与 dpi（实测，不猜）

- 读取 PNG 实际像素尺寸；`px / (dpi / 25.4) = mm`。300 dpi 时换算系数为 **300 / 25.4 = 11.811 px/mm**，反向 `mm = px / 11.811`。
- 文件名与实物可能不符：实测某「菱形100mm」运输标志整图为 1417×2550px = **119.97×215.90mm**，文件名只描述菱形部分。按文件名裁切会误判 → 交付命名须写出整图尺寸，或标 `需人工复核`。
- 尺寸为设计假设值时（未现场量桶身）→ 标 `需人工复核`，不写成「已达标」。

### 第 2 步 · 复算区块坐标（用源脚本／实测，不用目测）

- 有生成脚本时：读脚本里的常量与 `wrap()`，按同款字体与自适应高度**重算**区块 y 坐标，而不是从缩略图估值。
- 无脚本时：用图像分析定位区块边界，并在报告里写明「坐标来自图像量测，精度 ±N px」；量不准的区块不虚构参数，标 `需人工复核`。
- 输出统一为 `regions[]`：`id / type / x,y / w,h / font_mm / fg / bg`，单位 mm。

### 第 3 步 · 构造四份输入（现状与改进分开）

实测任务用的策略，可直接复用：

1. 现状正标
2. 现状背标（代表款 A，含 SDS 与 GHS）
3. 现状背标（代表款 B，验证配色/文案差异）
4. 改进建议版

**现状稿与改进稿必须分开跑、分开出结论**，不能把改进版数字写进现状报告。每份报告首行都要有执行声明。

### 第 4 步 · 实测布局回灌闭环（真实改版时用）

```text
视觉规格表（先设计）
  → 设计脚本按真实文案重绘，同时输出 layout.json（实测 box_bottom / 行数 / assert 结果）
  → 由 layout.json 生成 design_input.json（mm 坐标、wrapped_lines、copy_references、placeholder）
  → 跑 check_visual_spec.py 复验
  → 发现缺陷真修，再复验；不改文档凑数
```

`layout.json` 至少包含：`box_bottom_px`、安全区硬界、各区块实测行数与 `wrapped_lines`。**脚本不能生成设计**，只能判断已提出的方案。

## 三、三类实测踩坑（已写进脚本判据）

1. **像素取整把阈值卡掉**：`round(15mm × 11.811) = 177px` 反算是 **14.986mm < 15mm**，被 `check_visual_spec.py` 判 `不通过`。改为**向上取整** `178px = 15.07mm` 才通过。凡阈值边界一律向上取整后复验，不靠四舍五入。
2. **中文断行把标点甩到行首**：逐字断行会把句号「。」单独占一行。渲染器 `wrap_cjk()` 已实现禁则（行首收束标点并入上一行、行尾开启标点移到下一行）；实测 `wrapped_lines` 可回灌给校验器复验。实测案例中四段行数 8→7，底边距同时改善。
3. **文案承诺与版面元素不对应**：背标印「扫码获取 SDS」但版面无二维码 → 判 `不通过`，依据是**标签自述与版面不一致**，不是「农药二维码强制项」（该规则对本批不适用）。输入里用 `copy_references: ["qrcode"]` 声明，由校验器核对版面是否真有二维码区块。

> 二维码若只是预留位，必须标 `placeholder: true` 并写进「待业主拍板」：**占位 ≠ 已具备**，不得当作已有追溯能力，也不放可扫的假码。

## 四、零改动纪律（审查既有文件时默认开启）

用户要求「不能动包内任何内容／任何原文件」时：

1. 动手前用 `scripts/snapshot_unchanged.py --root ... --out baseline.txt` 记录全部原文件 SHA256 + 字节数（实测任务基线 29 / 579 个文件）。
2. 运行时设 `PYTHONDONTWRITEBYTECODE=1`，避免生成 `__pycache__`。
3. 所有产物**只写新建的独立子目录**，不覆盖任何已有文件。
4. 交付前 `--compare baseline.txt` 复核，报告写明「新增 0 / 删除 0 / 变化 0」；复核不通过不得宣称零改动。

## 五、边界

- 本方法只产出**可校验的几何与结构输入**，不判断文案合规、法规现行效力、商标图样一致性。
- 反算坐标有量测误差；量不准的项标 `需人工复核`，不虚构参数。
- 改版稿是**设计稿不是印稿**；印刷参数采用包内默认值时须写「采用默认值，需印厂确认」。
- 版式通过 ≠ 文案合规；占位 ≠ 已具备；法规条款须复核现行有效版本；不构成法律意见。
