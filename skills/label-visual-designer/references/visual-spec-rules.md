# B 域 · 标签视觉规格规则

> 适用：印在产品／包装上的实体标签的**版式与视觉设计**。
> 与 `domain-b-label-compliance.md` 的分工：那份管「写什么／不能写什么」，本份管「放在哪／多大／什么颜色／能不能印」。
> ⚠️ **本规则表是设计规格，不是法规**；不构成法律意见；涉及法规的条款须复核现行有效版本；印刷工艺参数以印厂规范为准。

---

## 零、承袭与增量（不宣称首创）

| 承袭 | 增量 |
|---|---|
| 本机 `brand-delivery-compliance-expert` → `print-preflight-checker` 的印刷基础参数（出血、CMYK、字体嵌入、300dpi、100% K、TAC） | 把印刷预检从「检查导出稿」前移到「设计阶段就定版式参数」 |
| 海巍驱蚊咨询报告 §4.3.1：商标置于四角、面积 ≤ 标签 1/9、字号不大于农药名称 | 转成可计算的面积比与四角区域判定 |
| `agency-agents-zh` → `design-ux-architect.md`：信息层级、栅格、设计令牌视角 | 标签专属的五层信息层级 + `tokens.css` / `tokens.json` 输出 |
| WCAG 2.1 相对亮度与对比度公式（公开标准） | 用于标签底色/字色的可计算校验 |
| 通用排版实践（视距与字高、静区、双语字号比） | 整合成标签专属规则表与可执行脚本 |

**本次真正新增的只有三件**：标签专属的五层信息层级与栅格规格、可计算的版式校验脚本、可渲染的 SVG 样张与设计令牌输出。以上参数均为既有实践的结构化整理，**不宣称首次发现任何设计规律**。

## 一、信息层级（强制优先，不可倒置）

| 层 | 内容 | 视觉要求 |
|---|---|---|
| L1 `mandatory` | 法定强制标注：登记证号、生产许可证、警示语、成分、净含量、可追溯二维码 | **最优先可视**；字号不得小于 L4；不得被装饰遮挡 |
| L2 `product-name` | 品类名称 / 产品名 | 主视觉；字号上限受商标限制约束 |
| L3 `brand` | 品牌与商标 | 四角、面积 ≤ 1/9、字号 ≤ 产品名称字号 |
| L4 `claim` | 功效／卖点 | 受禁用词表约束；不得压过 L1 |
| L5 `decor` | 底纹、色块、装饰线 | 不得覆盖 L1 文字区；只进出血、不进安全区边界 |

> 这套顺序是设计判断的核心：多数「标签不好看」的问题，根因是 L4 抢了 L1 的位置，而不是配色不好。

## 二、页面与栅格

| 项 | 默认值 | 说明 |
|---|---|---|
| 单位 | mm | 所有坐标、字号按毫米计 |
| 出血 `bleed_mm` | 3.0 | 底色／图形延伸区，**文字不得进入** |
| 安全边距 `safe_mm` | 5.0 | 所有文字与码必须在安全区内 |
| 栅格 | 4 列 / 4mm 基线 | 区块边界对齐栅格，避免随手摆 |
| 裁切框 | W×H | 成品尺寸 |

用户给了印厂规范就**用印厂规范覆盖默认值**，并在报告里写明「采用客户印厂规范」；没给时写「采用默认值，需印厂确认」——不能假装默认值是通用标准。

## 三、字号与可读性

- 最小字号按区块类型取 `config/visual-rules.json → type.min_font_mm`。
- 视距约束：`字高 ≥ 视距(mm) × 0.003`（经验值，需在目标视距实测确认）。
- **两者取较大值**作为该区块的字号下限。
- 双语排版：中文为主，英文副文 ≥ 主字号的 0.7 倍。
- 对比度：按 WCAG 2.1 相对亮度公式计算，`L = 0.2126R + 0.7152G + 0.0722B`（各通道先做 sRGB 线性化），`CR = (L亮 + 0.05) / (L暗 + 0.05)`。正文 ≥ 4.5:1，大字（≥4mm）≥ 3:1。

> 对比度只解决「能不能看清」，不解决「这句话能不能写」。后者走合规规则包。

## 四、商标与强制图形

| 项 | 规则 | 来源 |
|---|---|---|
| 商标面积 | ≤ 标签总面积的 1/9（0.1111） | 海巍驱蚊报告 §4.3.1 |
| 商标位置 | 四角区域内 | 同上 |
| 商标字号 | 不得大于产品名称字号 | 同上 |
| 二维码 | 边长 ≥ 15mm；静区 ≥ 4 个模块（≈ `4 × 边长 / 21`）；扫码可追溯；不得压安全边距 | 设计通用实践 + 追溯要求 |
| 条码 | 最小条宽 ≥ 0.25mm | 印刷通用实践 |

## 五、印刷工艺约束

| 项 | 阈值 | 处理方式 |
|---|---|---|
| 色彩模式 | CMYK（专色须标注） | 印厂规范优先 |
| 总墨量 TAC | ≤ 300% | 超出标 `不通过` |
| 最小线宽 | ≥ 0.2mm | 低于标 `不通过` |
| 黑色文字 | 100% K，不用四色黑 | 需印厂确认 |
| 图像分辨率 | ≥ 300dpi | 需印厂确认 |

## 六、可计算校验项（`check_visual_spec.py`）

| 事项 | 脚本能做 | 脚本不能做 |
|---|---|---|
| 对比度 | ✅ 按 WCAG 公式算比值 | ❌ 判断配色是否好看／符合品牌 |
| 字号 | ✅ 类型下限 + 视距下限 | ❌ 判断字体选择是否合适 |
| 安全边距 | ✅ 几何越界 | ❌ 判断视觉平衡 |
| 商标 | ✅ 面积占比、四角判定 | ❌ 判断商标图样是否与注册证一致 |
| 二维码 | ✅ 边长、静区、越界 | ❌ 扫码验证内容 |
| 印刷 | ✅ TAC、线宽、K 值、dpi 数值比对 | ❌ 判断实际印刷效果 |
| 信息层级 | ✅ L1 存在且字号 ≥ L4 | ❌ 判断文案是否合规、是否夸大 |
| 法规效力 | ❌ | ❌ 由用户／法务复核 |

**样张是设计稿，不是印稿**：`render_label_proof.py` 输出的 SVG 用于评审与沟通，不含真实产品信息，不得直接下厂。

## 七、设计评审五问（出稿前必过）

1. 站在目标视距，L1 强制项是不是最先被看到？
2. 最小字号与对比度都过了吗？
3. 商标面积／位置／字号三项都过了吗？
4. 二维码静区够不够、有没有压安全边距？
5. 印厂规范有没有覆盖默认值？没覆盖的项有没有标注「需印厂确认」？

五问全过才出样张。任何一问不过，退回规格表改，不靠「先发一版再改」糊过去。

## 八、输出清单

1. 视觉规格表（`templates/visual-spec-template.md`）
2. 版式校验报告（Markdown + JSON，首行执行声明）
3. SVG 样张（可开标注层）
4. `tokens.css` / `tokens.json` 设计令牌
5. 待拍板项（配色、字体、品牌取舍一律交回用户）

## 九、边界

- 不判断违法与否、不预测处罚，不构成法律意见。
- 不替代印厂工艺确认、不替代扫码实测、不替代商标图样核对。
- 版式参数须与合规结论**分开出**：版式通过 ≠ 文案合规。

## 十、v1.2 实测回灌规则（2026-11-19 桌面标签审查／真实改版）

承袭包内原有的五层层级、栅格、WCAG 2.1 与印前参数；增量是把 H100Z 背标改版中暴露的四类问题写成可复用判据。**不宣称首次发现任何设计规律**。

### 10.1 文案声明—版面元素一致性

文案写「扫码获取 SDS／完整版随货」时，版面必须有对应二维码区块；写「应急咨询电话」时必须有对应区块。缺了判 `不通过`，依据是**标签自述与版面不一致**，不是套用其他域的二维码强制项（先判适用性）。输入用 `copy_references` 声明，由 `check_visual_spec.py` 核对。

### 10.2 中文断行禁则

行首不得出现 `。，、；：！？）】》」』”’%‰℃`，行尾不得出现 `（【《「『“‘`。渲染器 `wrap_cjk()` 实现禁则；真实排版脚本实测的 `wrapped_lines` 回灌给校验器复验。实测案例：句号被单独甩到一行，加禁则后四段行数 8→7，底部安全余量同时改善。

### 10.3 占位 ≠ 已具备

二维码预留位、应急电话占位提示、生产日期／批次空白值区，都是**占位**。须标 `placeholder: true`、列进「待业主拍板」，报告写清「不得当作已具备追溯能力／已恢复电话」。不放可扫的假码，不编造号码。

### 10.4 规则来源域适用性

「商标须置四角、面积 ≤1/9、字号 ≤ 产品名」来自**卫生用农药标签项目**（海巍驱蚊咨询报告 §4.3.1）。用于工业化学品等其他域时先判适用性；适用性未确认 → `需人工复核`，不自动判 `不通过`。每条规则都要能说出它从哪个域来。

### 10.5 阈值边界与实测回灌

- 像素换算阈值一律**向上取整**后复验（177px = 14.986mm 判不通过，178px = 15.07mm 通过）。
- 文件名与实物尺寸不符（「菱形100mm」整图实为 119.97×215.90mm）有误导读裁切风险，标 `需人工复核`。
- 完整方法见 `references/visual-reverse-engineering.md` 与 `templates/redesign-spec-template.md`。
